### Opening a PR

Invoked at the end of every other playbook, and before each push to the branch of an open PR.

Work from a git worktree off trunk, and keep unrelated work out of it. For a push to an open PR, make the worktree from that PR's branch. Rebase into small, landable commits. Run `/deslop` over the diff before commit, and `/no-comments` before the review gate. Before you commit, merge, or deploy from a worktree, list the live agents and stop every one that holds it, including grandchildren you never launched. Confirm each stop, then run `git status` and read the tree you are about to ship.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`. When the work came from a tracker ticket, link it in `## Why` with the closing syntax from `docs/agents/issue-tracker.md`, for example `Closes #12`.

**Review gate.** Before you open a PR, draft or ready, run an independent review of the final diff. This includes a draft that the user asked for. When a script opens the PR, run the gate before you run the script. When a playbook opens the PR early, as Autopilot-full does, run the gate at the code-ready head instead, before you report that head. When new behavior, a redesign, or a large new diff lands on a PR after its gate, run the gate again over the PR diff from its base before you report that head. A rebase, a merge-conflict resolution, or a minor fix does not start a new gate. Skip the gate only when the diff changes nothing but docs, comments, generated files, or a version or config value that no code reads in a new way. Skill, playbook, and prompt text counts as code, not docs. Spawn `pdstack:thermo-nuclear-review-subagent` on the "judgment and prose" model. Give it the worktree path, the base, and the head SHA. The agent reads the diff at that SHA itself. Never count your own review, passing tests, or CI as this review. Fix each high or medium finding, or write down why it stays. After a fix, run one more review on the new diff. Do not run a third. The gate passes when no high or medium finding stays open without a reason. If you cannot spawn a subagent, ask your parent to run the gate on your head. When no one can run it, do not open the PR, except as a draft that the user asked for. If the PR is open, keep it from merge-ready. In both cases, report `BLOCKED: independent review`. A multi-phase plan's review-gated set names the PRs that wait for the operator's review, and does not change this gate.

**Large diffs.** When `git diff --shortstat <base>...<head>` counts more than 2,000 inserted plus deleted lines, not counting generated files and lockfiles, split the gate by component. A component is the finest of a project, a package, or a directory. Split until each component has at most 2,000 changed lines. Spawn one reviewer for each component and give it that component's paths. Spawn one more reviewer over the whole diff that looks only for faults that cross components. The follow-up review after fixes uses the same split.

**Gate comment.** The agent that owns the PR posts one PR comment for each gate, as soon as the PR exists. The comment starts with `review-gate: passed <sha>` or `review-gate: BLOCKED: independent review <sha>`, where `<sha>` is the head the last reviewer read. It lists each finding that stays open, with its reason. Fixes after that review do not change the SHA in the comment.

**Open PRs.** A push to the branch of an open PR gets the same bar as a new PR, whether it comes from Babysit, a build playbook, or a follow-up message in chat. A PR that a playbook opens early, as Autopilot-full does, follows that playbook until its code-ready report. A push that only replays existing commits, such as a rebase, a restack, or a retarget, follows the playbook that made it, such as Shipping step 4, so its patches and its gate stay as they are. Before each other push:

- Push to the PR that owns the code. In a stack, that can be a lower PR than the one the user names. If the owning PR merged, open a new PR on top of the rest of the stack, or off trunk, and run this whole playbook. If it closed without a merge, ask the user whether to reopen it, carry the work into a new PR, or drop the change.
- Read the PR's base with `gh pr view <pr> --json baseRefName` or `origin pr view <pr>` at each push, because a child's base can change to trunk after its parent merges. Fetch it, and use `origin/<base>` for every diff here and in the gate.
- Run `/deslop`, `/no-comments`, and the stack-pack standards review over the new commits, and verify the change on the surface it touches. When the push changes what the title or body says, rewrite them per the title and body rules above.
- Find the last `review-gate:` comment posted by the account you post from (`gh api user --jq .login`, or the Origin account with `origin pr view <pr> --comments`). Run the gate when no such comment exists, unless the **Review gate** skip covers the whole PR diff. Run it also when that comment says `BLOCKED`, or when `git fetch origin <sha>` cannot get the gated SHA. Otherwise apply the rerun rule to all work since the gated `<sha>`, not only this push. `git range-diff --right-only $(git merge-base <sha> origin/<base>)..<sha> origin/<base>..HEAD` marks each commit since the gate with `>` or `!`. A plain diff from `<sha>` is wrong after a restack, because it also counts the parent's changes.
- After a push to a lower PR, rebase each child onto its parent's new tip per `references/merge-safety.md`. Inside a babysit, report that restack instead, per `playbooks/babysit.md`.

Stack follow-ups by base branch. Open PRs ready, through the run's PR tool with `draft: false`. Without one, use `gh pr create` without `--draft`, or `origin pr create --status open` when Origin's CLI resolves the repository. Open a draft only when the user asks for one. Opening a PR does not start a babysit.

A subagent that opens a PR runs `/deslop`, `/no-comments`, and the review gate, and posts the URL.
